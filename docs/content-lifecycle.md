# Единый редактор, обучение, продажи и сохранение результатов

## Что изменилось для пользователей

### Администратор

В **Админ-центре → Модули** появилась библиотека с поиском, черновиками, опубликованными и архивными модулями. Кнопка **«Редактировать»** открывает отдельный рабочий экран.

В редакторе можно:

- создать модуль без ZIP, добавить уроки и каталоги файлов;
- создать урок прямо из файла: «Материалы → Новый урок из файла» делает файл основным материалом; имена не перезаписываются, урок не публикуется автоматически;
- редактировать название, описание, текст урока и его место в структуре;
- загрузить несколько файлов сразу, в том числе перетаскиванием;
- заменить файл, переименовать его, переместить в другой урок или общие материалы;
- менять порядок уроков и файлов кнопками вверх/вниз;
- выбрать несколько файлов и переместить их в архив;
- восстановить материалы из архива или предыдущую **версию содержимого файла**;
- защитить ручной текст от ZIP-замены, просмотреть историю текста урока и восстановить нужную версию;
- включить тест для урока после подготовки вопросов; новые ручные уроки не требуют теста автоматически;
- опубликовать, снять с публикации, архивировать и восстановить модуль;
- обновить **именно этот модуль** из ZIP без удаления и создания копии.

Библиотека открывается самостоятельно: тяжёлый расширенный редактор и его фоновые опросы не загружаются без необходимости. При сетевой ошибке есть повтор загрузки, а не вводящее в заблуждение «модулей нет».

**Редактор один:** «Материалы», «Тесты», «Настройки и доступ», «Обновить из ZIP», «Архив». Старые ссылки `?mid=…&sid=…` ведут в этот редактор, а не во второй интерфейс. В «Тестах» редактируются формулировки, 2–5 вариантов, один/несколько правильных ответов, объяснения, порог, таймер и число попыток (0 — без ограничения). Отдельно включается итоговый тест, собираемый из обязательных уроков. Аудитория и теги задаются в «Настройках и доступе».

У урока выбираются первый экран (`auto`, материал или текст) и основной файл. «Предпросмотр урока» показывает несохранённый черновик тем же компонентом, что и экран ученика; внешняя кнопка «Как видит ученик» открывает сохранённую версию. Большие тексты не пересылаются целиком при каждом обновлении рабочей области: полный текст загружается при редактировании.

Изменение банка создаёт новую версию теста: старые ответы и вопросы не переписываются. Ни ZIP, ни AI не включают тесты автоматически.

Редактор предупреждает о несохранённых изменениях при переходе по ссылке, выходе, Back и закрытии страницы. Фоновое завершение импорта не заменяет открытый черновик настроек или вопросов; при изменении редакции черновик теста остаётся на экране с предупреждением о конфликте. При конкурентном изменении сервер возвращает `409`: нужно перечитать данные, а не молча перезаписывать чужую работу. Черновики редактора пока не являются серверным автосохранением — сохраняйте их перед длительным перерывом.

### Ученик

Один экран объединяет содержание модуля, просмотр и переход к тесту. **Материал открывается первым**, если автор не выбрал текст. «Материал», «Текст урока» / импортированный «Конспект» и «Все файлы» переключаются вкладками: длинный извлечённый текст больше не стоит над документом. Конспект вспомогательный, исходную вёрстку смотрят в файле. Есть поиск по названиям материалов, папки и хлебные крошки. На телефоне содержание сворачивается; шапка больше не растягивает страницу по горизонтали.

Начало теста — явное действие. Незаконченная попытка возобновляется, ответы сохраняются в `sessionStorage` текущего пользователя/браузерной вкладки. Повторная отправка после потери HTTP-ответа возвращает уже записанный результат, не создавая ещё одну попытку или повторный XP. Смена браузера/устройства не переносит локальные черновики ответов. После отправки карточка следующего шага ведёт сразу к следующему уроку, тесту или завершению модуля, без ручного поиска в содержании. Ответы оцениваются по точным буквам вариантов: «A» больше не принимается из строки «A1», посторонние буквы и лишние выбранные варианты дают неверный ответ; обёртки `(A)`, `A.`, `А)` и разделители допустимы. Порог и таймер берутся из снимка начатой попытки. После сдачи есть разбор последней попытки: правильные ответы/объяснения раскрываются после зачёта либо исчерпания конечного числа попыток. При безлимитных попытках — после зачёта. Простой непустой ответ на старый `case/ANY` больше не считается знанием: такие банки нужно проверить администратору. Непроверяемая старая активная попытка не расходует попытку при отказе проверки.

Каталог различает начало, продолжение и сохранённый зачёт; пустой поиск не выдаётся за отсутствие модулей. Статусы не обрезаются на мобильном экране, активная вкладка основной навигации остаётся в видимой части.

На дашборде показан фактический следующий шаг: урок, тест урока, итоговый тест или общие материалы. Различаются начало, продолжение, обновления, завершённое обучение и отсутствие доступных модулей; вымышленного прогресса или ссылки на несуществующий модуль нет. Отдельного раздела «Справка» нет: подсказки встроены в те экраны, где они нужны, а быстрый старт открывается из шапки и работает без видео — вместо технических переменных окружения ученик видит инструкцию с доступным клавиатурным диалогом.

## Семантика прогресса

**Заработанный зачёт и знание текущей редакции — разные показатели.**

- `completed` — модуль уже зачтён, в том числе до изменения материалов.
- `current_completed` — выполнены все актуальные шаги.
- `completed_at`, `completed_revision` — когда и в какой редакции сохранён зачёт.
- Новые уроки не помечаются прочитанными автоматически.
- Замена/перемещение файла, изменение порядка, обновление вопросов и ZIP-обновление не отнимают уже заработанный зачёт.
- `viewed_revision` — последняя открытая редакция; `has_updates` учитывает изменения файлов даже без новых обязательных шагов. Открытие снимает уведомление о редакции, но не отмечает новые уроки изученными.
- Для обновлённого завершённого модуля каталог показывает сохранённые 100% и предложение открыть новые материалы.
- Сводный `percent` — средняя доля выполнения по модулям, где заработанный зачёт считается 100%. `current_percent` и счётчики шагов отдельно описывают текущие материалы. Ученики и административные отчёты используют один сервис расчёта.
- Архивные уроки и каталоги не добавляют обязательные учебные шаги. Пустой модуль не считается автоматически завершённым.
- Обязательная повторная аттестация после изменения программы **не включается автоматически**. Если нужен новый обязательный курс/цикл аттестации, создавайте его явно, а не сбрасывайте старую историю.

> Миграция восстанавливает зачёты из **сохранившихся** прочтений и попыток. Если прежняя версия приложения уже физически удалила историю при переимпорте, восстановить эти записи можно только из резервной копии.

## Как обновлять ZIP

Откройте нужный модуль → **Обновить из ZIP**. Не удаляйте существующий модуль и не используйте первичный импорт для его обновления.

Правила сопоставления:

1. Сначала — стабильный исходный путь (`source_path`).
2. Для старых уроков без исходного пути — только однозначное совпадение нормализованного названия и типа.
3. Порядок и приблизительное сходство названий не используются как идентичность.
4. Отсутствующие в новом ZIP материалы сохраняются. Ненужное можно явно убрать в архив.
5. Ручные названия, порядок, перемещения, архивное состояние и существующие тесты сохраняются.
6. Изменившиеся файлы получают новую версию с прежним идентификатором. SHA-256 исходных байтов хранится отдельно от SHA-256 преобразованного файла: повтор того же источника не запускает лишнее преобразование/загрузку. Старые записи без надёжного source hash не получают предположительный backfill.
7. Новые уроки при целевом обновлении создаются без обязательного теста. Импорт не запускает скрытую регенерацию и не меняет публикацию.
8. Новый импортированный текст управляется импортом (`content_mode=import`). Ручная правка или восстановление переключают его в защищённый режим (`manual`). Несовпадающий текст из ZIP не затирает ручной: отчёт показывает предупреждение. Для импортированного урока разрешение следующей ZIP-замены можно включить явно.
9. Существовавшие до миграции уроки считаются ручными. История текста (`content_version`, `LessonRevision`) начинается с последующего изменения, а не воссоздаёт неизвестные прошлые версии. Исторические тексты из S3 сохраняют ключ и bucket, чтобы прежняя версия оставалась доступной.
10. У вручную загруженного файла без привязки к источнику совпадение имени не является разрешением на замену: импорт останавливается с понятным конфликтом. Переименуйте файл в ZIP/редакторе. Для старого импортированного файла остаётся однозначное legacy-сопоставление.
11. Текст урока и прикреплённые файлы — отдельные сущности: при ручной замене вложения проверьте и при необходимости отредактируйте текст урока.

Единственная внешняя папка-обёртка автоматически раскрывается (кроме специальной `_module`). Структура после раскрытия: файлы в корне ZIP → уроки; каталоги верхнего уровня → каталоги материалов; `_module/` → общие файлы. Неоднозначное переименование исходного пути может создать новый материал; прежний останется на месте, а отчёт покажет предупреждение.

Обновление подготавливается вне блокировки модуля. Публикация изменений — одна транзакция с проверкой редакции. Доступ учеников во время подготовки сохраняется. Отмена после коммита не может отменить уже применённые изменения; такая задача сообщает об успешном применении, а последующие действия прекращаются.

Ограничения по умолчанию:

- файл через редактор: **512 МиБ**, настройка `CONTENT_UPLOAD_MAX_BYTES`;
- ZIP через редактор: **1 ГиБ**;
- ожидание загрузки через браузер/Next.js: **15 минут**;
- распаковка ZIP: до 12 000 файлов, 2,5 ГБ суммарно, 750 МБ на один элемент, ограничение коэффициента сжатия;
- ссылки, выход из каталога распаковки и дубли путей в ZIP запрещены.

Первичный потоковый/S3 multipart-импорт сохранён для крупных исходных загрузок, но лимиты безопасной распаковки всё равно действуют. Новая загрузка получает новый ключ: совпадение имени, размера и `mtime` больше не означает совпадение содержимого. Явное возобновление multipart использует ранее полученные `object_key` и `upload_id`, а не неявную общую сессию по имени файла.

### Подготовка видео и документов

Загрузка/ZIP сохраняют **точные оригиналы**. Импорт, подготовка браузерных копий и авторская проверка тестов — три независимые операции. `AssetRendition` хранит состояние и копию для конкретной версии источника; это не замена `ContentAsset` и не новая редакция курса.

- После SQL commit диспетчер API каждые 30 секунд доставляет outbox в очередь `corelms_media`. У старого файла подготовка запускается при первом открытии просмотра.
- Отдельный `worker_media` использует ffmpeg/ffprobe. При необходимости видео перекодируется в MP4, H.264/yuv420p, AAC stereo, до 1920×1080 и 30 fps, faststart. Подходящее видео до 60 fps/level 4.2 можно ремультиплексировать без повторного сжатия; готовая совместимая faststart MP4 используется без копирования.
- Поддерживаются MP4, MOV, M4V, MKV, AVI, WebM, WMV, FLV, MPEG/MPG, MTS/M2TS, 3GP, OGV. Повреждённые файлы, неизвестные кодеки, DRM и произвольные плейлисты не гарантируются.
- DOCX/PPTX до 25 МиБ готовятся в PDF через LibreOffice. В API/обычном worker LibreOffice не требуется: он включён только в Docker target `media`. Быстрый текстовый просмотр остаётся явной альтернативой, а не имитацией исходной вёрстки.
- Плеер/просмотр показывают ожидание, готовность и ошибку. Скачивание оригинала не зависит от успешности конвертации; у администратора есть повтор подготовки. Позиция воспроизведения переносится при переходе с совместимого исходного видео на готовую копию.
- Состояние очереди и SQL-claim восстанавливаются после сбоев. Устаревшие источники и архив проверяются перед работой и публикацией; старый worker не может перезаписать новую версию. До трёх автоматических повторов после оборванного claim, затем явная ошибка и ручной повтор. При замене старый процесс замечает неактуальный источник на контрольной точке.
- При отмене/таймауте завершается вся группа процессов конвертера. Файлы лежат в отдельном временном каталоге. LibreOffice получает отдельный профиль, отключённые макросы, нерабочий HTTP-прокси и окружение без credentials приложения. **Это не полноценная OS-песочница:** для недоверенных документов нужны дополнительная изоляция и ограничения egress/доступа к файловой системе на инфраструктуре.
- Лимиты: до 1 ГиБ источника/выхода медиа, 45 минут видео и 3 минуты Office по умолчанию, 2 encoder threads; Compose — один media-процесс, 1,5 CPU, 1536 МиБ RAM, 128 PID. Для `/tmp` нужен запас диска минимум под источник и копию (рекомендуется от 3 ГиБ на worker), не маленький RAM tmpfs. Следите за OOM, диском, очередью и состояниями `failed`.
- Копии в `renditions/` входят в retention set. Повторное восстановление того же неизменяемого источника переиспользует уже готовую копию. Потерянное подтверждение SQL commit не является разрешением удалить возможно опубликованный объект.

Старые endpoint/worker пакетной **замены** исходников отключены: HTTP `410`, а функции старых RQ-задач явно завершаются ошибкой до каких-либо записей. Нельзя одновременно запускать старую версию приложения и новую.

### Генерация — только проверяемый черновик

«Тесты» показывает, в скольких уроках ещё нет вопросов, и умеет одним запуском поставить черновики для всех уроков (если AI настроен) или только для уроков без тестов; статус каждого урока виден прямо в редакторе. За один запуск — до 50 уроков, повторный запуск не дублирует уже идущую или успешную работу. AI-черновик для одного урока использует выбранный основной документ (до пяти кандидатов) либо текст урока. Если текст выбран первым экраном, он имеет приоритет. Для PDF проверяются первые 20 страниц, без OCR. Для видео требуется конспект: распознавания речи нет. Можно явно вставить нужный фрагмент.

Внешний AI-провайдер — настроенный OpenRouter. В запрос идёт не более **12 000 символов**, и результат сообщает фактический источник/объём и предупреждает об усечении. Пустые/непроверяемые результаты не подменяются эвристическими вопросами или выдуманными объяснениями. AI может ошибаться — проверка фактов остаётся обязанностью автора.

Черновик хранится до 7 дней в Redis/RQ и доступен только администраторам. Он привязан к отпечатку **материалов этого урока** (текст, основной файл, вложения, версии, порядок), а не ко всей редакции модуля: правка другого урока, публикация или сохранение банка вопросов не делают его устаревшим. Изменение самого урока требует нового черновика. Он не меняет действующий тест. Можно заменить вопросы в форме или добавить новые к существующим (до 100), проверить и нажать «Сохранить тест». Потерянный ответ enqueue оставляет известный ID для возобновления; недоступность Redis не выдаётся за истечение черновика. Старые автопубликующие задачи и endpoint регенерации отключены.

## Продажи: Google Sheets и файлы

Это два независимых источника:

1. **Ссылки и видео** — Google Sheets. Лист со столбцами `name/link` или `название/ссылка` создаёт блок ссылок; `tab/name/link`, `вкладка/название/ссылка` или `раздел/название/ссылка` создают категории видео. Поддерживаются обычные URL и адреса именованных гиперссылок/`HYPERLINK`; формулы не вычисляются приложением. Разрешены только корректные HTTP(S), без userinfo, управляющих символов, обратных слешей и недопустимых портов. Неверные строки/заголовки показаны в предупреждениях администратору.
2. **Фото / Каталоги** — управляемые `SalesEntry → ContentAsset`. Суперадминистратор создаёт папки, загружает до 50 файлов за раз, заменяет, переименовывает файлы, просматривает версии, архивирует/восстанавливает. Папка в архиве скрывает все вложения, включая прямые API-ссылки; восстановление родителя не отменяет самостоятельный архив файла. Перемещение/переименование папок пока не реализовано. Обычный admin не получает полномочия superadmin в продажах.

Кеш Sheets: 3 минуты свежести, последняя удачная копия до 7 дней, минутная пауза после ошибки, single-flight между процессами и локальный fallback при сбое Redis. Ошибка сети/неполный ответ не заменяют успешную копию пустым списком. UI различает `fresh/stale/loading/error/unconfigured`, показывает дату последнего успешного чтения и ссылку «Редактировать таблицу» для superadmin. Принудительное обновление — также только superadmin.

Транспорт создаётся отдельно на чтение, timeout 8 секунд на HTTP-запрос, максимум 30 листов × 1000 строк × 3 столбца. Названия листов корректно экранируются в A1. Это ограничение диапазона и содержимого ячеек, **не жёсткий байтовый лимит скачанного Google-ответа**.

Настройки приложения: `SALES_LINKS_SPREADSHEET_ID` и либо `SALES_LINKS_SERVICE_ACCOUNT_JSON` (дать service account право чтения таблицы), либо `SALES_LINKS_GOOGLE_API_KEY` для соответствующим образом открытой таблицы. Подключение Google Sheets в Arena и настройки работающего приложения — разные вещи; никаких настоящих credentials в репозиторий не добавляется.

Старые `sales/photos/` и `sales/catalogs/` лениво регистрируются без переноса/удаления байтов. За один запрос усваивается до 500 записей из S3; список в SQL отдаётся страницами по 100. При большом каталоге есть «Загрузить ещё из хранилища». Переименованный, заменённый или архивированный источник не появляется заново после сканирования. Управляемые ключи — `managed/sales/<section>/<uuid>`, не отображаемое имя. Папки имеют до 20 уровней и до 1000 UTF-8 байт пути. Некорректные/слишком длинные старые имена не удаляются — о пропусках сообщается.

Запись проверяет редакцию раздела и коллизии, включая ещё не зарегистрированные старые объекты. Предыдущие байты остаются в `AssetRevision`. Старые подписанные PUT/физические delete endpoint продаж и произвольная запись через `/assets/presign-upload` отключены. Сбой передачи останавливает очередь: перед повтором нужно проверить список, а не автоматически послать дубликат.

## Просмотр файлов

Внешний `view.officeapps.live.com/embed.aspx` больше не используется. Приватная presigned-ссылка не передаётся стороннему Office Viewer; ошибка `OnLoad is not defined` этого iframe больше не блокирует XLSX.

| Формат | Поведение |
|---|---|
| XLSX, XLSM, XLS, CSV, TSV | Внутренний просмотр таблиц, переключение листов, только чтение |
| DOCX, PPTX | Фоновая PDF-копия; явный упрощённый текстовый просмотр и оригинал как fallback |
| TXT, MD, JSON, LOG | Текстовое представление |
| PDF | Авторизованный same-origin поток и нативный просмотр; явное сообщение/скачивание, если браузер не поддерживает PDF |
| Растровые изображения, аудио | Нативный просмотр/плеер, если браузер поддерживает формат |
| Поддерживаемые видео | Фоновая MP4-копия; исходник всегда доступен |
| HTML, SVG, XML и неизвестные форматы | Только скачивание оригинала; активное содержимое не исполняется на origin LMS |

**Excel-калькулятор не пересчитывается в LMS.** Формулы показываются как содержимое ячеек, макросы и внешние ссылки не исполняются. Для изменения значений и расчётов скачайте оригинал и откройте его в Excel/LibreOffice. Это предсказуемый безопасный просмотр, не онлайн-редактор таблиц.

Лимиты предпросмотра: 25 МиБ входного файла, 100 МиБ распакованных данных Office, 5 000 ZIP-элементов, 500 строк × 60 колонок, 2 000 символов в ячейке, 300 000 символов текста, 100 слайдов. Ограничение/ошибка просмотра не мешает скачиванию оригинала.

XML Office читается потоково с ограничениями глубины, узлов, атрибутов и незавершённого токена; DTD/сущности запрещены. XLSX проходит предварительную проверку metadata/shared strings/styles и размера строки до `openpyxl`. Проверяются объявления XML-частей, дубли ZIP-имён и общий бюджет слайдов PPTX. CSV ограничивается и по размеру логической строки, включая многострочные поля. На процесс API выделено два одновременных слота загрузки/разбора: при занятости возвращаются `429`, `Retry-After` и предложение повторить, скачивание оригинала остаётся отдельно.

Те же просмотрщики используются в уроке, авторском предпросмотре и продажах. При внутреннем/loopback адресе S3 или mixed-content скачивание идёт через авторизованный same-origin поток; браузер не обращается к `localhost` сервера. Для публичного HTTPS S3 сохраняется прямое скачивание.

Для PDF важны **все** прокси: точный путь `/api/backend/assets/<id>/stream` получает `X-Frame-Options: SAMEORIGIN`; остальные страницы остаются с `DENY` в production. Исключение добавлено в Next.js, nginx и Caddy. Не устанавливайте поверх него общий `DENY` на CDN/внешнем балансировщике.

## Хранение и ограничения совместимости

- Архив — логическое исключение из обучения, не физическое удаление.
- Файлы записываются в уникальные `_versions/`-ключи, исходные ZIP — в уникальные `_sources/` или `uploads/sources/`.
- Восстановление файла создаёт новую версию, не удаляя текущую; актуальные расположение и основа имени сохраняются, расширение соответствует восстановленному содержимому. Коллизия имён не перезаписывает соседний файл.
- Объекты, которые могли успешно записаться при потерянном подтверждении коммита/очереди, не удаляются по предположению об ошибке.
- Автоматическая физическая TTL-очистка, purge модулей по неполному сканированию S3 и CLI `cleanup_orphan_upload_zips.py --delete` отключены. Диагностика не является разрешением на удаление. Очистка устаревших **незавершённых multipart-сессий** — отдельная операция, не удаляющая завершённые файлы.
- Хранилище будет расти с количеством версий и исходников. Нужны мониторинг объёма и отдельная согласованная политика retention, резервные копии и проверяемая офлайн-процедура. Не включайте S3 Lifecycle expiration на этих префиксах.
- Старый файл, связанный одновременно с несколькими модулями, защищён от изменения из одного редактора. Для независимого редактирования нужна отдельная копия; автоматическое разрушительное «переприсваивание владельца» не выполняется.
- Старые подписанные URL могут действовать до истечения срока даже после закрытия доступа. Новые API-запросы проходят проверку прав. Production-срок скачивания по умолчанию ограничивается пятью минутами.
- Смена S3 endpoint/учётной записи не мигрирует объекты автоматически. Не меняйте bucket/credentials без переноса и проверки старых версий.

## Сеансы и вход

- Разные входы создают разные SID, даже при одинаковом User-Agent. Список в личном кабинете показывает реальные активные сеансы текущего пароля; можно отозвать конкретный/остальные.
- Access JWT привязан к SID и версии хеша пароля. Redis — авторитет сеанса, а не необязательный кеш. Выход/отзыв делает ранее выданный access недействительным; короткая refresh-grace не воскрешает удалённый SID.
- Refresh выполняет WATCH/MULTI-транзакцию. В Next.js объединяются только одновременно выполняющиеся запросы с тем же токеном; успешные токены не кешируются после завершения запроса.
- Смена пароля сохраняет текущий сеанс и отзывает прежние на других устройствах. Сброс администратором/одноразовой ссылкой не позволяет использовать старые credentials. Конкурентная проверка старого пароля не заимствует версию нового пароля после SQL commit.
- При Redis/сети `503` не подменяется «неверным паролем»; временная ошибка refresh не очищает cookies/черновик. Если сервер не подтвердил отзыв при выходе, браузерные cookies очищаются с отдельным предупреждением; при невозможности самого запроса выход не изображается успешным.
- Принудительная смена временного пароля проверяется на API, а не только экраном. Роль берётся из БД; обычный admin не получает операции superadmin. Сроки/политики остаются в настройках приложения.
- Старый access без SID требует обновления через сохранившийся refresh; пригодный legacy-refresh обновляется до новой схемы. Часть старых/истёкших сеансов может потребовать повторного входа. Не меняйте JWT secret или Redis при обновлении случайно.

## Внедрение существующей установки

**Изменения ещё не являются выполненным обновлением production.** Сначала проверяйте копию БД и копию/изолированный bucket. Не запускайте тестовые фикстуры на рабочей БД.

1. Остановите приём новых операций. Не возобновляйте старые очереди автоматически: сначала сохраните бэкап и разберите активные задания. Согласованно завершите или отмените известные операции и остановите API и все старые workers: старый код не должен продолжать писать после миграции.
2. Создайте и проверьте резервные копии PostgreSQL и S3. Сохраните текущую конфигурацию и версию приложения. Обязательно сохраните Redis/RQ-состояние перед первым пересозданием контейнера.
3. Соберите API, frontend и **все** workers из одной версии кода.
4. Примените Alembic до `0024` один раз, отдельным шагом. `0021` добавляет состояние архива/редакции/исходного пути, историю файлов, зачёты, связи версий тестов, уникальность прочтений и идентификаторы попыток. `0022` добавляет режим и историю текста и отдельный source checksum. `0023` — показ/основной файл урока, порядок вопросов, переключатель итогового теста, outbox браузерных копий и обратимую библиотеку продаж. `0024` — таблица `app_settings` для настроек AI, Google Sheets, S3 и лимитов платформы (секреты шифруются, `enc:v1:`).
5. Запустите API, затем workers и frontend, затем ingress. Не допускайте одновременно старые и новые workers.
6. Проверьте доступ администратора и ученика, один ранее завершённый модуль, XLSX/PDF, замену файла, откат версии, закрытый доступ и обновление ZIP. Отдельно проверьте большой файл через фактический nginx/Caddy/CDN.
7. В Compose Redis теперь использует `redis_data:/data`, AOF `everysec`, `noeviction`, `REDIS_MAXMEMORY` (256 МБ) и запас памяти контейнера `REDIS_MEMORY_LIMIT` (640 МБ). Это предотвращает незаметное вытеснение заданий/сеансов. Переполнение требует вмешательства, а не игнорирования: мониторьте `used_memory`, ошибки OOM, длину очередей, AOF rewrite и свободный диск. AOF everysec не даёт нулевую потерю при аварии питания. Резервные копии всё равно нужны.

### Первый перенос непостоянного Redis

**Не запускайте новый Compose Redis до переноса его состояния.** В старой конфигурации данных в новом томе ещё нет. Подготовьте и проверьте процедуру восстановления на копии; не используйте `FLUSHDB` или `down -v`.

Один из вариантов для прежнего `redis:7` после остановки всех writers:

1. На ещё работающем старом Redis включите AOF (`redis-cli CONFIG SET appendonly yes`). Дождитесь `aof_rewrite_in_progress:0`, `aof_rewrite_scheduled:0`, `aof_last_bgrewrite_status:ok` и `aof_last_write_status:ok` в `INFO persistence`.
2. Штатно остановите **старый** контейнер Redis, не удаляя его. Скопируйте всё его `/data/` (включая AOF manifest и appendonlydir) в закрытый каталог резервной копии. Например: `docker compose cp redis:/data/. backups/pre-0024-redis/` после создания каталога с правами `700`.
3. Восстановите эту копию в **пустой** новый том `redis_data`, сохранив владельца/права. Не объединяйте два разных набора AOF и не перезаписывайте существующий том вслепую. Убедитесь, что Compose project name остаётся прежним.
4. Запустите только новый Redis и проверьте чтение AOF, выбранный DB index, ключи сессий/очереди и readiness. Только после этого запускайте API/workers. Запишите время/результат и храните исходную копию для отката.

Это план переноса, а не выполненная миграция вашего сервера; Docker-операции восстановления в данной среде не выполнялись.

Пример команд после подготовки окна обслуживания (не инструкция запускать это без бэкапа):

```bash
# Старые writers остановлены; Redis уже безопасно перенесён и проверен.
# Не выполнять этот блок до подготовки резервных копий и процедуры выше.
mkdir -p backups
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backups/pre-0024.dump

docker compose build backend frontend worker_import worker_regen worker_default worker_media
# --entrypoint обязателен: штатный entrypoint контейнера запускает API.
docker compose run --rm --no-deps --entrypoint alembic backend upgrade head
docker compose up -d backend worker_import worker_regen worker_default worker_media frontend
# Затем запустите используемый ingress: nginx ИЛИ Caddy согласно вашему режиму.
```

### Настройки AI и Google Sheets в интерфейсе

`/admin/settings` — единая точка для токена AI, таблицы продаж и файлового хранилища (S3). Отдельных «runtime»-форм в диагностике больше нет: там только состояние сервисов и ссылки на настройки. Значения сохраняются в `app_settings`; секреты шифруются (`SETTINGS_ENCRYPTION_KEY`, иначе производный ключ от `JWT_SECRET_KEY`). Приоритет: сохранённое в интерфейсе → устаревшие `runtime:llm` в Redis → переменные окружения. Поэтому токен, введённый администратором, применяется API и всеми воркерами без перезапуска и **не требует** `ALLOW_RUNTIME_LLM_OVERRIDES=true`.

Проверка токена — `POST /admin/settings/ai/test`: для OpenRouter вызывается авторизованный `/key` (список `/models` у OpenRouter публичный, поэтому одного его недостаточно), для остальных совместимых API — `/models` с токеном. Генерация не делает отдельного health-запроса: ошибки авторизации возвращает сам запрос черновика. Google Sheets проверяется чтением списка листов; при 403 интерфейс показывает адрес сервисного аккаунта, которому нужно выдать доступ.

Тесты генерируются только как **черновики**: источник — текст урока, документ (PDF/DOCX/PPTX) или вставленный текст (до 12 000 символов; сканы без текстового слоя и видео не распознаются), результат сохраняется автором вручную. Пакетная подготовка ограничена 50 уроками и не дублирует уже готовые черновики. Видео автоматически не расшифровывается. Подробная инструкция по миграции — в `README.md`, раздел «Обновление и миграции».

Добавленные настройки есть в `.env.example`. `S3_PUBLIC_ENDPOINT_URL` должен быть доступен браузеру, не `localhost` контейнера. Browser API-запросы остаются относительными, через `/api/backend`.

**Откат:** остановить writers и восстановить согласованный backup БД вместе с прежней версией приложения. `alembic downgrade` удаляет новые метаданные жизненного цикла; это не безопасный production rollback после появления новых изменений. Downgrade/re-upgrade проверяется тестом только на одноразовой БД.

### Границы проверки

Актуальный локальный стенд использует PostgreSQL 16.2, настоящий Redis/RQ и S3-совместимый **Moto**, а не боевой S3. Браузер — Chromium; UI проверяется с живым API и отдельно production build. Реальная конвертация AVI → H.264/AAC MP4 и воспроизведение проверяются. Google Sheets API/сбои покрыты изолированными ответами, UI stale-состояния — явно имитированным ответом.
